## 项目概览

本实验实现了一个基于物理的三维布料仿真系统，核心内容包括：

- 将布料离散化为 20×20 的质点网格，通过弹簧连接建模弹性形变
- 实现三种数值积分方法（显式欧拉、半隐式欧拉、隐式欧拉），并可实时切换对比稳定性差异
- 利用 Taichi 的 GPU 并行计算加速物理更新，通过 `ti.kernel` / `ti.func` 的架构设计最小化 Kernel 启动开销
- **扩展**：在结构弹簧基础上补充剪切弹簧与弯曲弹簧，并实现布料与球体的碰撞响应

## 必做内容

### 场景初始化

布料被离散为 `N×N`（默认 20×20）的质点网格，铺设在三维空间的水平面上，两个上角点固定。

初始化操作被**拆分为三个独立的 `@ti.kernel`**，在 Python 侧按顺序调用，保证 GPU 的状态同步（每个 kernel 结束即隐式同步屏障）：

```
init_positions()       → 初始化质点位置、速度、受力、固定标记
init_springs()         → 构建弹簧拓扑（质点对 + 原长）
init_spring_indices()  → 同步用于线框渲染的索引缓冲
```

关键参数：

| 参数 | 值 | 说明 |
|------|-----|------|
| `N` | 20 | 网格分辨率 |
| `dt` | 5e-4 | 时间步长（秒） |
| `k_s` | 10000.0 | 结构弹簧劲度系数 |
| `k_d` | 1.0 | 阻尼系数 |
| `mass` | 1.0 | 质点质量 |
| `max_velocity` | 50.0 | 速度钳制上限 |

---

### 力学计算与防爆处理

两个核心计算函数使用 `@ti.func` 声明，在编译时**强制内联**到调用方的 Kernel 中，避免 GPU 函数调用开销。

**`compute_forces_on(pos, vel, force)`**

分两阶段计算合力：

1. 对每个质点施加重力与阻尼力：
   $$f_i = mg - k_d v_i$$

2. 遍历所有弹簧，按胡克定律计算弹力并累加（使用 `ti.atomic_add` 避免多线程写冲突）：
   $$f_a = -k_s \left(|x_a - x_b| - l\right) \frac{x_a - x_b}{|x_a - x_b|}$$

Taichi 保证同一 kernel 内多个顶层 `for` 循环**顺序执行**，因此两阶段之间无需额外同步。

**`clamp_velocity(vel, idx)`**

对每个质点的速度向量进行范数钳制，防止显式欧拉在大时间步下出现数值爆炸：

$$v_i \leftarrow \begin{cases} v_i & \text{if } |v_i| \leq v_{max} \\ \dfrac{v_i}{|v_i|} \cdot v_{max} & \text{otherwise} \end{cases}$$

### 积分求解器实现

三种方法各自封装为一个 `@ti.kernel`，将**受力计算与位置/速度更新合并在同一 kernel 内**，每帧仅触发 1 次 kernel 启动。

#### 显式欧拉（Explicit Euler）

使用当前时刻状态预测下一时刻，容易发散：

$$x_{t+1} = x_t + v_t \Delta t$$
$$v_{t+1} = v_t + a_t \Delta t$$

- **特点**：实现最简单，但在弹簧刚度较大时极不稳定，会迅速爆炸。

#### 半隐式欧拉（Semi-Implicit Euler）

先更新速度，再用新速度更新位置，能量有界，相对稳定：

$$v_{t+1} = v_t + a_t \Delta t$$
$$x_{t+1} = x_t + v_{t+1} \Delta t$$

- **特点**：兼顾效率与稳定性，是布料仿真中最常用的方法。

#### 隐式欧拉（Implicit Euler）

使用**定点迭代法**（Fixed-point Iteration）近似求解未来时刻的隐式方程，迭代 3 次：

$$v_{t+1} = v_t + a(x_{t+1}, v_{t+1}) \Delta t$$
$$x_{t+1} = x_t + v_{t+1} \Delta t$$

迭代展开使用 `ti.static(range(3))` 在**编译期静态展开**，无运行时循环控制开销。

- **特点**：无条件稳定，在大阻尼参数下布料收敛明显更快，但每步计算量约为前两种方法的 3 倍。

## 选做内容（扩展）

选做扩展在 `cloth_simulation_ext.py` 中实现，完全向后兼容必做功能，三个选做特性均可通过 GUI 开关**运行时热切换**。

### 完整弹簧模型

在结构弹簧（Structural）的基础上，补充了**剪切弹簧（Shear）**和**弯曲弹簧（Bending）**。

#### 弹簧类型对比

| 类型 | 连接关系 | 劲度系数 | 作用 |
|------|---------|---------|------|
| 结构弹簧 Structural | 水平/垂直方向相邻质点（步长 1） | 10000 | 维持布料的基本网格形状 |
| 剪切弹簧 Shear | 对角方向相邻质点（步长 1，斜向连接） | 8000 | 抵抗剪切变形，防止布料沿对角线过度拉伸 |
| 弯曲弹簧 Bending | 水平/垂直方向隔一个质点（步长 2） | 3000 | 模拟布料的弯曲刚度，防止折叠过死 |

剪切弹簧示意（每个质点连接右下和左下对角，避免重复连接）：

```
o---o---o
|\ /|\ /|
| X | X |    ← 对角线即为剪切弹簧
|/ \|/ \|
o---o---o
```

弯曲弹簧示意（间隔一个质点的连接，跨越中间质点）：

```
o       o       o
│←──────────────→│   ← 弯曲弹簧（跨越中间质点）
o       o       o
```

#### 实现细节

- `spring_stiffness` 字段存储每根弹簧的独立劲度系数，`compute_forces_on` 中统一按此系数计算，无需区分弹簧类型
- 开关热切换时调用 `init_cloth()` 重建弹簧拓扑，`max_springs` 扩展至 `N*N*8` 预留足够容量
- 三类弹簧均在同一个 `init_springs()` kernel 内完成，通过 `enable_shear[None]` / `enable_bending[None]` 的条件分支控制

**观察效果**：

- 仅结构弹簧：布料沿对角方向容易过度变形，折叠时呈"菱形网格"失真
- 添加剪切弹簧：布料更为挺括，对角变形明显减小
- 同时启用弯曲弹簧：布料折叠时边缘更圆滑，不会出现锐角折叠

### 球体碰撞检测

在场景中心放置一个静止球体，物理更新时检测布料质点与球面的穿透并修正。

#### 碰撞响应算法

每个积分步骤的末尾，对每个非固定质点调用 `resolve_sphere_collision()`：

1. **穿透检测**：计算质点到球心的距离，若 `dist < sphere_radius + particle_offset (0.01)`，则判定为穿透
2. **位置修正**：沿碰撞法线将质点推回到球面外：
   $$x_i \leftarrow x_{sphere} + \hat{n} \cdot (r_{sphere} + 0.01)$$
3. **速度修正**：移除速度的法向分量（仅对朝向球心的速度生效，避免拉扯），并施加切向摩擦衰减：
   $$v_i \leftarrow (v_i - v_n \hat{n}) \times 0.9$$

#### 实现细节

- `sphere_center` 定义为 `shape=(1,)` 的向量场（而非标量场 `shape=()`），以满足 `scene.particles()` 对 `shape[0]` 的要求
- `resolve_sphere_collision` 以 `@ti.func` 内联到三个积分 kernel，与碰撞开关 `enable_collision[None]` 联动，开关关闭时零额外开销
- 球体在渲染侧通过 `scene.particles(sphere_center, radius=sphere_radius[None], ...)` 显示为红色大粒子

## 实验结果与分析

### 数值积分方法稳定性对比

| 方法 | 稳定性 | 能量特性 | 典型表现 |
|------|--------|---------|---------|
| 显式欧拉 | 差 | 能量单调递增 | 低阻尼下迅速爆炸，质点飞散 |
| 半隐式欧拉 | 好 | 辛结构，能量有界 | 长时间运行稳定，轻微震荡 |
| 隐式欧拉 | 最佳 | 能量耗散 | 收敛快，高阻尼下几乎无震荡 |

### 阻尼系数影响

- `k_d = 1.0`：布料自然飘动，震荡明显
- `k_d = 5.0`：阻尼增大，布料更快稳定，半隐式与隐式差异变小

### 弹簧模型影响

- 仅结构弹簧：适合基础验证，布料可沿对角方向过度变形
- 结构 + 剪切：布料抗剪能力增强，更接近真实织物行为
- 全部启用：弯曲刚度使布料折叠时保持自然曲率，更具真实感

## 架构要点

**为什么将初始化拆分为多个 kernel？**

Taichi 中每个 `@ti.kernel` 调用结束时会隐式触发 GPU 同步屏障。弹簧初始化依赖质点位置（用于计算原长），若合并在一个 kernel 内，位置写入和弹簧读取可能发生竞争。拆分后，`init_springs()` 能保证读取到完整的初始位置数据。

**为什么使用 `@ti.func` 而非多个 kernel？**

`@ti.func` 在编译期强制内联，不产生额外的 GPU kernel 启动调用。Kernel 的启动本身有 CPU-GPU 通信开销（通常 10–100µs 量级），在每帧 40 个物理子步的循环中，减少 kernel 数量能显著提升帧率。

**为什么使用 `ti.static(range(3))` 展开隐式欧拉迭代？**

`ti.static` 告知 Taichi 编译器在代码生成阶段展开循环，生成 3 份重复的静态代码，避免 GPU 上的动态分支和循环控制指令，进一步减少运行时开销。
